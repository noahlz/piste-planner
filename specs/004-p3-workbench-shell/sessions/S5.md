## What S4 handed you, and must not be re-derived

S4's handoff section carries the full tables. The conventions, so you catch a
violation on sight:

- **`timeZoom` is minutes per pixel.** `geometry.pxPerMinute` is its reciprocal
  and the only place the scale is inverted. Never open-code `1 / timeZoom` —
  a reviewer already caught one shadowed redefinition.
- **Both axes are window-relative and neither clamps.** A block scrolled off
  the left or above the top gets a negative coordinate and slides under the
  edge. Do not "fix" that into a zero.
- **Row ranges are inclusive both ends; time ranges are half-open** `[start,
  end)`. `intersectsTimeRange` is that rule, executable — use it rather than
  writing the comparison again.
- **The day header band is an overlay, not a row**, so `rowsPerDay ===
  stripsTotal` and the flat index is `day * stripsTotal + strip`. The whole
  constant-time resolution depends on it.
- **An over-large `rowScroll` pins to the last _full window_**, via
  `maxRowScroll` — **not** to `totalRows - 1`. On a 90-row layout,
  `rowScroll: 200` resolves to a first row of **70**, not 89. S4's orchestrator
  got this wrong in a review message and a subagent caught it.
- `ROW_HEIGHT_PX` is compact 16, normal 24, tall 36. The gutter is 72px, the
  day band 38px.
- **Blocks read `categoryFill` and `categoryInk` from `palette.ts`.** Do not
  introduce a third place a visual constant lives.

**Segment boundaries** come from `geometry.eventTimeSegments`, which *reads*
the engine's `ScheduleResult` and recomputes no duration. Two shapes need care,
both already pinned by tests: a flighted event fills `flight_a_*`/`flight_b_*`
while `pool_start`/`pool_end` still span both flights, and `de_total_end`
extends past the last block by the medal tail, which **gets no block**.

## Two defects S4 found by looking at it, which are yours to fix

Neither was caught by any test. They were found by mounting the canvas in a
throwaway preview and screenshotting it, and **they become user-visible the
moment T040 mounts it for real.**

**1. The day band covers strip 1 entirely and clips strip 2.** The band is a
38px sticky overlay positioned at the top of its day's rows, with no
compensating offset, so on every day group the first strip is never visible and
the second is half-cut. `MatrixCanvas.tsx`'s own docblock argues that giving the
header layout space would break `blockY`'s alignment — that argument is sound
as far as it goes, but a constant `HEADER_HEIGHT_PX` applied uniformly to the
gutter, the SVG and `headerTop` preserves the alignment while reserving the
space. S4 deliberately applied only the opacity half of this finding and left
the layout half, because it changes the canvas's vertical model. **It is yours
to decide and fix.** Whatever you choose, cover it: a test asserting the first
strip's row is not underneath the band.

**2. The default view opens on the middle of the night.** `timeScroll` defaults
to `0` — midnight — while a competition day starts at 08:00, so at the default
zoom the first ~480px of canvas is empty and the schedule is shoved right.
`Fit to day` corrects it perfectly, which is the point: nobody should have to
click it on first load. This is **T040's**, because T040 is what makes the
matrix the default view, and a default view showing eight hours of empty night
is a defect in exactly that. Fixing `DEFAULT_VIEW_STATE.timeScroll` is the
obvious move; check what that does to `viewState.test.ts` and update it in the
same task if the default changes.
