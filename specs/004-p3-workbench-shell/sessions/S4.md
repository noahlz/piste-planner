## The things most likely to go silently wrong

**1. `timeZoom` is minutes per pixel, and the geometry formula wants pixels per
minute.** `src/store/viewState.ts` declares `timeZoom: number // minutes per
pixel`. data-model.md's block formula is
`(minutes − windowStart) × pxPerMinute`. So `pxPerMinute = 1 / timeZoom`.
Getting this inverted produces a canvas that renders, scrolls and zooms – just
wrong, in a way that looks plausible at one zoom level. Assert a concrete
pixel value at two different zooms in T028, not just that the value changed.

**2. Windowing arithmetic is where an off-by-one passes every test that only
checks the shape of the answer.** Assert exact boundaries: the row at exactly
`scrollTop`, the row one before it, the last row that fits the viewport and the
first that does not. Same for the time window. A test asserting "some rows are
visible" is the failure mode this feature has already hit three times – read
S2's and S3's handoff sections on FR-009, the WARN-versus-ERROR gap and
`configEditing.test.tsx`, all of which passed while proving nothing.

**3. The sixteen category values must be enumerated from the real types, not
from a list you type out.** `Category` has eleven members and `VETERAN` expands
across the six `VetAgeGroup` bands, which is what makes sixteen. Derive the set
in `palette.ts` from `src/engine/types.ts` so a future twelfth category cannot
quietly lose its colour. T026 should fail if any value has no token.

**4. Day grouping is the only thing that makes row indexing non-trivial.** The
canvas is a sequence of day blocks, each a header band plus `strips_total`
rows. Resolve a flat index to its day and strip through a day-boundary lookup
in constant time – constitution IV forbids searching for it.

**5. Do not flip `DEFAULT_VIEW_STATE.viewMode` to `MATRIX`.** S1 recorded that
line as the one a later task is expected to change, and that task is **T040, in
S5**. Flipping it now, while the center still renders `ScheduleOutput` and the
toggle does not exist, blanks the center.

**6. A fixture reaching for a low fencer count crashes the render rather than
raising a finding.** `computePoolStructure` (`src/engine/pools.ts:25`) throws
for `fencerCount <= 1` and `initialAnalysis` calls it for every selected
competition regardless of placement. Use `strips_total` when you need an
invalid config – and `0` versus a small non-zero value are not interchangeable.

**7. T039 persists through `localStorage`, so S1's guard matters.**
`src/test-setup.ts` installs an in-memory `Storage` shim only when the ambient
`localStorage` lacks working methods – a Node ≥24 workaround that is a no-op on
CI's Node 22. Do not delete it as redundant. On this machine your zoom-
persistence tests exercise the shim, not jsdom's real `Storage`.
